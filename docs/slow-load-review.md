# Почему сайт грузится долго или показывает чёрный экран

Дата ревью: 2026-11-01. Проверено: полный проект `mersibo/ceomentality_full` (только чтение) и живой сайт ceomentality.ru. Код не менялся.

**Симптом.** Сайт долго показывает чёрный экран и полосу загрузки у адресной строки. Загрузочного экрана нет. С VPN и без. Изредка грузится нормально.

**Важно.** Сбой я не воспроизвёл: с моей сети сервер отвечает быстро (в среднем 0,33 с, максимум 0,82 с на 25 загрузок). Поэтому ниже вероятные причины, а не доказанные. Подтвердить нужно замерами на сервере и на телефоне (см. «Как проверить»).

## Вероятные причины (по убыванию)

### 1. Страницу не рисуют, пока не придут 5 CSS-файлов (наша часть, вероятнее всего)

- В `<head>` пять стилей: `loader.css`, `styles.css`, `typography.css`, `wallet-media.css`, `footer.css`. Пока все не загрузятся, браузер ничего не показывает.
- Сам загрузочный экран описан в `loader.css`. Если стили задержались, не видно ни его, ни сайта. Остаётся пустой фон браузера (в тёмной теме он чёрный) и полоса загрузки.
- Сервер отдаёт сайт по HTTP/1.1. Файлы идут очередью, а не одновременно.
- Сжат только HTML. CSS, JS, SVG и шрифты идут как есть, без gzip.
- Почему «то так, то так»: всё зависит от качества связи. На хорошей сети успевает, на плохой нет.

### 2. Загрузочный экран запускается слишком поздно (наша часть)

- Скрипт `loader.js` стоит последним из 13 скриптов с `defer`. Они выполняются по порядку, поэтому интро не начнётся, пока не загрузятся и не выполнятся все 12 перед ним.
- Страховочный таймер на 7 секунд стоит в inline-скрипте в `<head>` и считается от начала страницы, но он только убирает загрузочный экран. Если стили не пришли, экран всё равно не виден.

### 3. Сервер перегружен (сторона Геры)

- На одной машине: postgres, backend (2 воркера gunicorn), landing, frontend CRM, redis, bot, xray. Сборки Docker на том же сервере тоже едят память и процессор.
- Если памяти или процессора не хватает, nginx начинает отвечать с задержками. Это даёт долгий чёрный экран даже при идеальном фронте.
- Я не вижу сервер изнутри, поэтому это нужно проверить Гере.

### 4. Тяжёлая главная на слабых телефонах (наша часть)

- После загрузки на главной 3 441 DOM-узел и около 412 одновременных анимаций. Одно из полей состоит из 2 286 узлов.
- Случайный вариант первого экрана подгружает физику Matter.js.
- На старом телефоне страница может «подвисать» после загрузки. Это скорее про лаги, чем про чёрный экран, но усугубляет картину.

### 5. Старый кэш после деплоя (сторона Геры + наша)

- В `docker/nginx.landing.conf` для `.css`, `.woff2`, `.png`, `.svg` стоит кэш на 30 дней с `immutable`. Имена файлов без хеша.
- После деплоя у тех, кто уже заходил, новый HTML может встретиться со старым CSS. Получаются «старые» элементы и странные сбои. Мы уже видели это: у Геры оставалось старое меню и футер.
- Для `.js` и `.webp` кэш-заголовков нет вообще, поведение непредсказуемо.

### 6. Лимит запросов, если не передаётся IP (сторона Геры)

- `SecurityMiddleware` считает запросы по `X-Forwarded-For`. Если внешний nginx его не передаёт, все пользователи окажутся «одним IP». Лимит 60 запросов в минуту на `/api/v1/*` сработает на всех сразу.
- Это не чёрный экран главной, а «НЕТ СОЕДИНЕНИЯ» на страницах, которые ходят в API.

### 7. Долгое ожидание API на страницах приложения (наша часть, по мелочи)

- Таймаут запроса к API 15 секунд. Пока ждём, пользователь видит «ЗАГРУЖАЕМ.».
- Главную это не блокирует: каталог запрашивается без ожидания.

## Что подтвердилось

- API на показ главной не влияет. Ответы `/session`, `/catalog` и `/health` быстрые.
- Деплой свежий: живой сайт уже отдаёт наши `woff2` и `webp`.

## Как проверить

**Гере, на сервере:**

1. `docker stats` и `free -m` в момент, когда сайт тормозит. Видно, не упёрлись ли в память и процессор.
2. `docker logs` для nginx и backend за период сбоев: долгие ответы, 502/504, перезапуски.
3. Включить HTTP/2 и gzip (или brotli) для `css`, `js`, `svg`, `json` и шрифтов.
4. Убрать `immutable` для файлов без хеша в имени.
5. Проверить, что внешний nginx передаёт `X-Forwarded-For`.

**Нам, с телефона:**

1. Открыть сайт на телефоне через мобильную сеть, снять вкладку Network (Safari Web Inspector или Chrome DevTools). Смотреть, какой запрос висит и сколько он длится.
2. Сравнить с замером «с кэшем» и «без кэша».

## Что исправлено на нашей стороне (2026-11-01)

Привязки Геры не тронуты. `runtime-config.js` остался отдельным файлом и грузится перед остальным кодом: его по-прежнему правит `sed` в Dockerfile, и nginx отдаёт его без кэша. Код скриптов и API не менялся, команда `npm run build` та же. Режим `api` после `sed` проверен: страницы ходят в `/api/v1/session` и `/api/v1/catalog`.

1. **Белый фон сразу.** В `index.html` и `app.html` белый фон и `color-scheme: light` прописаны прямо в HTML. Пустой экран теперь белый, а не чёрный.
2. **Загрузочный экран без ожидания CSS.** При сборке `loader.css` вставляется прямо в HTML, экран виден, как только пришёл HTML.
3. **CSS одним файлом.** Остальные стили склеиваются в один `bundle.<хеш>.css`. Было 5 запросов, стал 1.
4. **JS одним файлом.** 12 скриптов склеиваются в один `bundle.<хеш>.js`, отдельно остаётся только `runtime-config.js`. Было 13 запросов, стало 2. Каждый файл внутри обёрнут в свой `try/catch`, поэтому ошибка в одном не ломает остальные, как и раньше.
5. **Загрузочный экран стартует первым.** Внутри бандла `loader.js` идёт первым, до тяжёлой подготовки главной.
6. **Хеш в именах бандлов.** После изменения кода имя файла другое, и старый кэш (`immutable` на 30 дней) не подсунет старые стили.
7. **Шрифты легче в 3,6 раза.** Из шести шрифтов убраны неиспользуемые символы. Оставлены латиница, кириллица, цифры, пунктуация, ₽, №, стрелки и все символы, которые встречаются в текстах сайта и юр. документах. Было 594 КБ, стало 163 КБ. Внешний вид не меняется.

Исходники для разработки не склеиваются, `npm run dev` работает как раньше. Склейка происходит только в `dist/` (`build.mjs`).

Проверили и оставили как есть:
- Анимации главной уже ставятся на паузу вне экрана и в фоновой вкладке (`typography.js`). Узлов много, но в простое они не нагружают процессор.
- Внешних скриптов, шрифтов и CDN нет, всё своё. Matter.js загружается локально и только для нужного варианта hero.
- Preload шрифта `inter-extrabold` нужен: им набран заголовок первого экрана.

Это конфиг сервера, у нас его нет: HTTP/2, gzip для css/js/svg/json/шрифтов, кэш для `.js` и `.webp`, `X-Forwarded-For`, проверка памяти и процессора, submodule `landing`, `deploy/` для vless-client.

- **Бот ходит в Telegram через VLESS-прокси.** Для политики персональных данных это ещё один аргумент в пользу вопроса о трансграничной передаче.
